Problem and Objective

The problem
Manual formatting is slow
Non-designer professionals spend up to 60–70% of total authoring time wrestling with coordinate placement, margin alignment, and visual inconsistencies rather than refining their core ideas.
Unstructured blank-canvas dilemma
Users are confronted with empty 16:9 canvases, creating cognitive friction and writer's block when attempting to formulate slide outlines from scratch.
Degradation of visual aesthetics
Free-form drag-and-drop mechanics allow arbitrary coordinate placement, resulting in broken hierarchies, mismatched margins, overlapping boxes, and visually unappealing slide decks.
Our objective
Prompt-to-slide schema synthesis
Decouple semantic content authoring from visual structural rendering, mapping prompts into strictly validated JSON data contracts.
Constrained responsive layout engines
Enforce mathematically proportioned 16:9 layout templates to preserve typographic hierarchy and prevent layout degradation.
Client-side multi-format export pipeline
Enable instant, high-fidelity exports into PDF, Word (.docx), PowerPoint (.pptx), images (JPG/PNG), and standalone web decks directly in the browser.

How Slide Generation & Export Works

1
Topic Input
User enters a presentation topic or opens an existing deck with custom requirements.
2
Schema Map
Content structures into validated JSON objects specifying slide titles, content bodies, and timestamps.
3
Live Canvas
React renders responsive 16:9 slides with real-time text editing, thumbnail navigation, and deck renaming.
4
Virtual Stage
During export, each slide clones into an off-screen 1280x720 node to strip input borders and cursors.
5
Multi-Export
The chosen engine compiles clean slides into PDF, Word (.docx), PowerPoint (.pptx), images, or web decks.
By decoupling semantic content authoring from visual structural rendering, PPT-GEN guarantees 100% design consistency across all presentation outputs.

Data and Slide Schema Design

Presentation Deck Schema
• id: string (e.g., 'proj-1', 'proj-172855...')
Unique identifier generated at creation, used for URL routing (/editor/:id).
• title: string (e.g., 'AI Product Pitch')
Deck title editable directly from the editor navigation bar or dashboard cards.
• updatedAt: string (e.g., 'Just now')
Timestamp showing last modification for dashboard sorting and project audit.
• slides: Array<Slide>
Central array containing all sequential slide entities belonging to the deck.
Slide Entity Schema
• id: number (e.g., Date.now())
Unique timestamp identifier ensuring reliable React key reconciliation and deletion.
• title: string
Slide heading text, mapped to H1 headers in PDF, Word, and PowerPoint exports.
• content: string
Multi-line body content, bullet points, and summaries preserved with pre-wrap whitespace.
• layout: '16:9' aspect-locked container
Enforces mathematical proportions, preventing visual degradation across all displays.
Strict JSON data models eliminate arbitrary pixel coordinates, guaranteeing deterministic, bug-free document compilation.

Challenges and Solutions

What went wrong How we fixed it
Free-form drag-and-drop caused overlapping boxes & broken margins Enforced mathematically proportioned, responsive 16:9 layout containers with CSS aspect-ratio locking.
Capturing live editor screen produced blurry text and input cursor artifacts Architected an off-screen virtual stage rendering clean semantic HTML at 2x High-DPI resolution.
Only active slide was mounted in DOM, preventing multi-slide PDF export Implemented sequential off-screen DOM staging to capture every slide sequentially into jsPDF and JSZip.
Client-side Word & PowerPoint export required heavy server roundtrips Integrated client-side docx and pptxgenjs compilers, allowing 100% in-browser binary generation.
Nested React Router collision crashed navigation on page reload Refactored App.jsx and main.jsx into a clean single BrowserRouter under StrictMode.
Monolithic CSS grew past 480 lines with maintainability bottlenecks Restructured into 236 lines of clean, categorized rules without losing any styling or animations.

Conclusion and Future Scope

Conclusion
PPT-GEN successfully demonstrates how decoupling semantic content authoring from visual design solves the "blank-canvas dilemma". By combining React 19, strict JSON schemas, and a client-side multi-format export pipeline (PDF, DOCX, PPTX, Images, HTML), users can author, customize, and export presentation-ready decks in seconds without design degradation.
